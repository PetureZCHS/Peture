# Peture 自建埋点与看板说明

本文档记录当前自建埋点体系的结构、Supabase 资源、事件定义，以及 Flutter Web 看板的启动方式。

## 当前状态

- 已保留友盟埋点，同时新增 Supabase 自建埋点通道。
- 已在 Supabase Cloud 创建埋点相关表，并部署两个新增 Edge Functions。
- 已验证 `analytics-collect` 可接收 Peture App 用户行为并写入 `analytics_events`。
- 看板以 Flutter Web 方式运行，通过 `APP_MODE=admin` 启动后台模式。
- 管理员权限由 `admin_users` 控制；只有 `enabled = true` 的 Supabase Auth 用户可访问看板数据。

## 数据流

```text
Peture App
  -> AnalyticsService
  -> SharedPreferences 本地队列
  -> analytics-collect Edge Function
  -> analytics_events

Flutter Web 看板
  -> Supabase Auth 登录
  -> analytics-dashboard Edge Function
  -> 聚合查询 analytics_events
  -> 图表和排行展示
```

## Supabase DB

迁移文件：

```text
supabase/migrations/20260513120000_analytics_events_dashboard.sql
```

相关表：

| 表名 | 用途 |
| --- | --- |
| `analytics_events` | 原始埋点事件表，保存用户行为、页面、模块、平台、时间、停留时长和 `properties`。 |
| `analytics_event_definitions` | 事件字典和白名单。`analytics-collect` 只接受 `enabled = true` 的事件。 |
| `admin_users` | 看板管理员表。`analytics-dashboard` 校验当前 Supabase Auth UID 是否在此表且启用。 |

关键字段：

| 字段 | 说明 |
| --- | --- |
| `user_id` | Peture App 用户 UID；与 Supabase Auth `auth.users.id` 一致。 |
| `anonymous_id` | 设备/安装级 ID，保存在客户端本地。 |
| `session_id` | 一次 App 埋点会话 ID。 |
| `event_name` | 用户行为事件名，必须存在于事件字典。 |
| `page_name` | 页面名，例如 `diary_compose`。 |
| `module` | 模块名，例如 `diary`、`expense`、`ai_image`。 |
| `duration_ms` | 页面停留或操作耗时，单位毫秒。 |
| `properties` | 事件扩展字段；客户端和 Edge Function 都会清洗敏感字段。 |

添加看板管理员：

```sql
insert into public.admin_users (user_id, role, enabled)
values ('替换为 Authentication -> Users 里的 UID', 'owner', true)
on conflict (user_id) do update set
  role = excluded.role,
  enabled = excluded.enabled;
```

## Supabase Edge Functions

| Function | 用途 | JWT |
| --- | --- | --- |
| `analytics-collect` | App 客户端批量上报埋点事件，做白名单校验、字段清洗、批量限制和入库。 | 允许无 JWT，但非匿名事件需要登录用户 token。 |
| `analytics-dashboard` | Flutter Web 看板查询聚合数据；校验 `admin_users` 后返回总览、排行、AI 使用和漏斗数据。 | 需要 JWT。 |

部署命令：

```bash
npx supabase functions deploy analytics-collect --project-ref dyxbvsnnrzvozcokhlfw --use-api --no-verify-jwt
npx supabase functions deploy analytics-dashboard --project-ref dyxbvsnnrzvozcokhlfw --use-api
```

注意：当前远端迁移历史和本地迁移历史不完全一致，避免直接使用 `npx supabase db push`。如只需要创建埋点表，应只执行对应 SQL 文件：

```bash
npx supabase db query --linked --file supabase/migrations/20260513120000_analytics_events_dashboard.sql
```

## 当前事件定义

| 事件名 | 模块 | 当前记录方式 | 说明 |
| --- | --- | --- | --- |
| `app_open` | `app` | `AnalyticsService.init()` | App 埋点初始化时记录启动/打开。 |
| `page_view` | `navigation` | `PageTrackerMixin` / `TrackedPage` | 页面进入或重新可见。 |
| `page_leave` | `navigation` | `PageTrackerMixin` / `TrackedPage` | 页面离开，并记录 `duration_ms`。 |
| `button_click` | `interaction` | 预留，调用 `AnalyticsService.track()` | 通用按钮点击事件。 |
| `feature_entry` | `interaction` | 预留，调用 `AnalyticsService.track()` | 进入某个功能模块。 |
| `form_submit` | `interaction` | 预留，调用 `AnalyticsService.track()` | 表单提交尝试。 |
| `ai_chat_start` | `ai_chat` | 预留 | AI 问诊请求开始。 |
| `ai_chat_success` | `ai_chat` | 预留 | AI 问诊请求成功。 |
| `ai_chat_error` | `ai_chat` | 预留 | AI 问诊请求失败。 |
| `diary_generate_start` | `diary` | `PetDiaryEdgeService` | 调用日记 v4 Edge Function 前记录。 |
| `diary_generate_success` | `diary` | `PetDiaryEdgeService` | 日记流式生成完成时记录。 |
| `diary_generate_error` | `diary` | `PetDiaryEdgeService` | 日记生成 HTTP / Dify / 异常失败时记录。 |
| `image_generate_start` | `ai_image` | 预留 | AI 生图开始。 |
| `image_generate_success` | `ai_image` | 预留 | AI 生图成功。 |
| `image_generate_error` | `ai_image` | 预留 | AI 生图失败。 |
| `expense_created` | `expense` | `SupabaseService.insertUnifiedExpense()` | 消费记录创建成功后记录。 |
| `pet_profile_created` | `pet_profile` | `SupabaseService.insertPet()` | 宠物档案创建成功后记录。 |
| `share_card_click` | `diary` | `AnalyticsService.logEvent()` | 日记分享卡片点击；同时保留友盟上报。 |
| `error_event` | `error` | 部分服务失败分支 | 客户端可见错误或关键业务失败。 |

匿名事件限制：

```text
app_open
page_view
page_leave
button_click
feature_entry
```

其他事件需要客户端携带 Supabase Auth token，`analytics-collect` 会解析 token 并写入 `analytics_events.user_id`。

## Flutter Web 看板

看板代码位置：

```text
lib/features/admin_analytics/
```

入口切换：

```text
--dart-define=APP_MODE=admin
```

### Windows 启动

在项目根目录打开一个新的 PowerShell 窗口：

```powershell
flutter run -d web-server --web-hostname 127.0.0.1 --web-port 8090 --dart-define=APP_MODE=admin
```

然后访问：

```text
http://127.0.0.1:8090
```

如果端口被占用，换端口：

```powershell
flutter run -d web-server --web-hostname 127.0.0.1 --web-port 8091 --dart-define=APP_MODE=admin
```

### macOS 启动

在项目根目录打开一个新的 Terminal 窗口：

```bash
flutter run -d web-server --web-hostname 127.0.0.1 --web-port 8090 --dart-define=APP_MODE=admin
```

然后访问：

```text
http://127.0.0.1:8090
```

端口被占用时同样可以改为 `8091` 或其他端口。

### 与 Android 模拟器并行运行

可以和 Android 模拟器里的 Peture App 同时运行。建议：

- 一个终端跑 App：`flutter run -d android`
- 另一个终端跑看板：`flutter run -d web-server ...`
- 只要 Web 端口不冲突，两者互不影响。

## 常用排查

- 看板返回 `403 Forbidden`：检查当前登录 UID 是否在 `admin_users` 且 `enabled = true`。
- 看板无数据：先确认 `analytics_events` 是否已有事件，再确认筛选条件和日期范围。
- `analytics-collect` 拒收事件：检查 `event_name` 是否在 `analytics_event_definitions` 且 `enabled = true`。
- 同设备切换账号时 `anonymous_id` 可能相同，这是预期；用户分析以 `user_id` 为准。
- 同一 App 进程内切换账号时 `session_id` 可能相同，这是当前实现的会话语义。
