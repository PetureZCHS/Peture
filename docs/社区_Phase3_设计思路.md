# 社区功能 Phase 3 设计思路

## 阶段回顾

- **Phase 1**：发帖 + 信息流（帖子列表、发布页、发现/关注 Tab）
- **Phase 2**：评论、点赞、收藏、关注（帖子详情互动、关注流）
- **Phase 3**：搜索 + 用户主页（+ 可选：附近真实数据、话题浏览）

---

## Phase 3 目标

在现有「发现 / 关注 / 附近」和顶部按钮基础上，补齐「搜得到、点得进人」的闭环：支持搜索帖子与用户，并从帖子进入作者主页查看其动态与关注关系。

---

## 1. 搜索

- **入口**：社区页顶部搜索图标，点击进入搜索页。
- **搜索页**：
  - 搜索框 + 可选 Tab：「帖子」/「用户」。
  - **帖子搜索**：按关键词对 `community_posts.content`（或标题）做模糊查询，结果以信息流卡片展示，点击进入帖子详情。
  - **用户搜索**：按昵称对 `users_profiles.nickname` 模糊查询，结果为用户列表（头像、昵称），点击进入该用户主页。
- **后端**：Supabase 使用 `ilike` 或全文检索（若有）实现模糊匹配；若无现成表结构，仅用 `content`/`nickname` + `ilike` 即可。

---

## 2. 用户主页（作者主页）

- **入口**：帖子详情页、信息流卡片、评论区的头像/昵称，点击后进入对应用户的主页。
- **页面内容**：
  - 顶部：用户头像、昵称、简介（若 `users_profiles` 有 bio 等字段）、关注数/粉丝数（若后端有或可查 `community_user_follows`）。
  - 关注/取消关注按钮（复用 Phase 2 的 `toggleFollow` / `isFollowing`）。
  - 下方：该用户发布的帖子列表（按 `author_id` 查 `community_posts`，按时间排序），样式可复用发现页卡片。
- **数据**：用户信息来自 `users_profiles`；帖子列表来自 `community_posts` 按 `author_id` 筛选；关注关系沿用 `community_user_follows`。

---

## 3. 可选扩展（后续迭代）

- **附近 Tab**：若 `community_posts` 增加经纬度或地区字段，附近 Tab 可改为按位置拉取附近帖子，替代当前 mock 数据。
- **话题/标签**：利用现有 `topic_ids`，增加话题列表页与「按话题筛选」的帖子流，形成话题浏览动线。

---

## 实现顺序建议

1. 搜索页 UI + 帖子/用户搜索接口与结果展示。
2. 用户主页页（含头像、昵称、帖子列表、关注按钮）+ 从帖子详情/卡片点头像或昵称跳转。
3. 按需补充附近真实数据或话题浏览。
