# 敏感审查灰度开关与回滚清单

## 一、后端开关（Supabase Edge Functions 环境变量）

- `ENABLE_TEXT_MODERATION`：文本审查总开关，默认 `true`
- `ENABLE_IMAGE_MODERATION`：图像审查总开关，默认 `true`
- `ENABLE_OUTPUT_MODERATION`：输出审查开关（AI 输出/日记输出/生图输出），默认 `true`

说明：
- 高风险链路建议保持 fail-close，不建议在生产关闭全部审查。
- 若第三方服务短时异常，优先切换为本地 fallback（保留开关为 `true`）。

## 二、灰度顺序

1. 批次 1：`nickname` / `owner_nickname` / `avatar`
2. 批次 2：`ai_input` / `ai_output` / `diary_input` / `diary_output`
3. 批次 3：`image_input` / `image_output`

每批最少观察 24 小时。

## 三、门禁指标

- `moderation.error.count / moderation.request.count < 1%`
- `moderation.block.count` 不突增（相对近 7 日均值变化 < 30%）
- 文本审查 P95 <= 1000ms
- 图像审查 P95 <= 3000ms（不含生图生成耗时）

## 四、回滚步骤

1. 前端回滚：恢复到上一个稳定版本（仅 UI/调用层回滚）。
2. 后端回滚：
   - 优先关闭 `ENABLE_OUTPUT_MODERATION`，观察 5-10 分钟。
   - 如仍异常，切换 `ENABLE_IMAGE_MODERATION=false`（保留文本）。
   - 极端情况下再切换 `ENABLE_TEXT_MODERATION=false`。
3. 保留 `moderation_logs` / `moderation_errors` 数据，不做回滚删除。

## 五、应急排查

- 通过 `traceId` 关联：
  - `moderation_logs.trace_id`
  - `moderation_errors.trace_id`
- 优先检查：
  - 鉴权失败（401）
  - 第三方 provider 延迟或失败
  - 存储桶权限与路径 owner 不一致
